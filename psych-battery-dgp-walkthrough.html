psych-battery-dgp.R: a four-test psychological battery simulator

Walkthrough: how the script works, and how to use it in Quarto

Aims

psych-battery-dgp.R is the shared infrastructure every other script in this set is built on. It simulates a battery of four correlated psychological tests — StuVoc1, StuVoc2, GK, ART3, grounded in Vermeiren et al. (2023) — and exposes exactly three independently controllable “dials”, because those three dials are what the surrounding teaching scripts each take turns holding fixed and varying:

  • (i) participant sample size (n) — how many people are in a study;
  • (ii) measurement error, via each test’s reliability — how noisy a single person’s score is;
  • (iii) the true (construct-level) correlation between two tests’ underlying abilities — what the correlation would be if both tests were measured without error; together with (ii), this determines how strong a correlation the observed scores actually show.

On top of the simulator sits a generic diagnostic/sweep engine (run_sweep(), summarize_sweep()) that repeats a correlation test many times over a grid of these dials and computes power, the empirical false positive (Type I) rate, sign consistency (Type S), the Type M “exaggeration ratio” (Gelman and Carlin 2014), and confidence-interval coverage — the same diagnostic quartet used in this project’s heavier Aims 1–2 glmer simulation work, here scaled down to run inline rather than as a background job.

The simulator isn’t just plausible — it’s checked against real numbers. Simulated at its default settings, it reproduces Vermeiren et al. (2023)’s own reported test statistics (means, reliabilities, inter-test correlations) closely, and a quick power sweep reproduces the power values the paper itself reports for a true r = .2 correlation at N = 40 and N = 200 (see the Validation section).

After working through it, you should be able to:

  • explain why reliability, true correlation, and observed correlation can’t be set independently of one another, and what build_sigma_true() / disattenuate() do about that;
  • generate a single study (simulate_battery()), a two-test focal pair (simulate_pair()), or a sweep over sample size/reliability/true correlation (run_sweep()), and read off power, Type I rate, sign consistency, the Type M exaggeration ratio, and coverage from the result;
  • explain why simulate_pair() exists as a separate function rather than always drawing from the full four-test correlation matrix.

Prerequisites / assumptions

  • Packages: ggplot2; MASS, called via :: only (so it never masks dplyr::select() if dplyr happens to be attached) — same convention as this project’s Aims 1–2 code; base R stats for uniroot(), integrate(), and cor.test().
  • Sourcing: standalone — no other script needs to be sourced first. This script is, in turn, a prerequisite for sampling-measurement-error.R, nhst-power.R, and error-rates-process-control.R.
  • Reader background: classical test theory terms (reliability, true score, attenuation) and basic ggplot2/cor.test() familiarity are assumed.

How it works: the process

\[ \text{Standardized true ability (correlated across tests):} \quad z_i \sim \text{MVN}(0, \Sigma_{\text{true}}) \] \[ \text{Per test } t \text{, calibrated ability:} \quad \theta_{ti} = \theta_{\mu,t} + \theta_{\sigma,t} \, z_{it} \] \[ \text{Per-item probability:} \quad p_{ti} = \text{guessing}_t + (1 - \text{guessing}_t) \cdot \text{plogis}(\theta_{ti}) \] \[ \text{4AFC tests (StuVoc1, StuVoc2, GK):} \quad \text{score}_{ti} \sim \text{Binomial}(n_{\text{items},t}, p_{ti}) \] \[ \text{ART3:} \quad \text{hits}_i \sim \text{Binomial}(60, p_{\text{ART3},i}), \quad \text{rejects}_i \sim \text{Binomial}(30, p_{\text{ART3},i}) \]

reliability and Σ_true are never set on the observed-score scale directly — the whole script exists to make that translation automatic:

The central design idea, same philosophy as sampling-distributions.R’s calibrate_ability(), generalized to four tests and two item-response mechanisms: you set the things that matter pedagogically — a test’s mean score, its reliability, and the observed correlation you want two tests to show — and the script solves numerically for the underlying ability parameters that reproduce them, rather than requiring you to work out the ability-scale numbers yourself.

Calibration machinery: expect_theta(), implied_moments_general(), calibrate_ability_general(), get_calibration()

implied_moments_general <- function(theta_mu, theta_sigma, n_items, guessing = 0) {
  p_fun  <- function(th) guessing + (1 - guessing) * plogis(th)
  p_bar  <- expect_theta(p_fun, theta_mu, theta_sigma)
  p2_bar <- expect_theta(function(th) p_fun(th)^2, theta_mu, theta_sigma)
  pq_bar <- expect_theta(function(th) { p <- p_fun(th); p * (1 - p) }, theta_mu, theta_sigma)

  mean_score  <- n_items * p_bar
  var_true    <- n_items^2 * (p2_bar - p_bar^2)
  var_error   <- n_items * pq_bar
  reliability <- var_true / (var_true + var_error)
  # ...
}

This generalizes sampling-distributions.R’s implied_moments() with one change: a guessing floor in p_fun(), which collapses back to the original model exactly when guessing = 0 (ART3’s case). Given a candidate (theta_mu, theta_sigma), it works out the mean score, the between-person (“true”) variance, the within-person (measurement-error) variance, and their ratio — reliability — that choice implies.

calibrate_ability_general() runs this backward: a nested uniroot() search (outer over theta_sigma, inner over theta_mu) for the parameters whose implied_moments_general() output matches a target mu and reliability, with the outer search bracket doubled automatically if the initial range doesn’t contain a root.

NoteA stop() and a warning(), not just one or the other

Two different failure modes are handled two different ways. If no bracket up to a generous ceiling contains a root at all (e.g. reliability = 0.999 requested for a 50-item test), that’s a genuinely unachievable target and calibrate_ability_general() stop()s with a message explaining why. But uniroot()/integrate() are only numerically exact up to their own tolerance, so even a successful search can land slightly off target — that’s checked separately against a tolerance argument (default 0.01) and only warning()s, since the calibration did still return a usable result.

get_calibration() wraps this in a simple cache, keyed on the rounded (mu, reliability, n_items, guessing) arguments — because a sweep calls it with the same arguments many times over (once per replicate within a grid cell), and re-running uniroot()/integrate() every time would be needless, measurable overhead at sweep scale.

Disattenuation: disattenuate() and build_sigma_true()

disattenuate
function (r_obs, reliability_x, reliability_y) 
{
    denom <- sqrt(reliability_x * reliability_y)
    r_true <- r_obs/denom
    if (abs(r_true) > 1) {
        warning(sprintf(paste("Target observed correlation r = %.2f is not achievable at", 
            "reliabilities %.2f and %.2f (it would require a true-score", 
            "correlation above 1); capping the true-score correlation at", 
            "%.3f."), r_obs, reliability_x, reliability_y, sign(r_true) * 
            0.999))
        r_true <- sign(r_true) * 0.999
    }
    r_true
}

This is the single formula the whole “three dials” design rests on: classical test theory says \(r_{\text{true}} = r_{\text{observed}} / \sqrt{\text{reliability}_x \cdot \text{reliability}_y}\) — usually used to estimate a disattenuated correlation from data. Here it’s run in the opposite direction: given a target observed-score correlation (one of the Vermeiren-grounded defaults, or an override), solve for the true-score correlation that, once measurement error is added back in via the per-test calibration above, will reproduce it.

build_sigma_true() applies this to every off-diagonal cell of a target observed-score correlation matrix to build the full 4×4 matrix that’s actually fed to the multivariate draw:

ev <- eigen(Sigma, symmetric = TRUE)
if (any(ev$values < 1e-8)) {
  warning("Sigma_true was not positive-definite after disattenuation; nudging to the nearest valid correlation matrix (eigenvalue clipping).")
  vals <- pmax(ev$values, 1e-6)
  adj <- ev$vectors %*% diag(vals) %*% t(ev$vectors)
  d <- sqrt(diag(adj))
  Sigma <- adj / outer(d, d)
  dimnames(Sigma) <- list(nm, nm)
}
NoteWhy a 4x4 matrix can stop being positive-definite

Disattenuating each pairwise correlation independently doesn’t guarantee the resulting matrix is still a valid correlation matrix (positive semi-definite) — pushing even one cell to an extreme value (as a sweep deliberately does) can make the implied matrix mathematically inconsistent as a whole. Rather than erroring out, build_sigma_true() nudges it to the nearest valid matrix by clipping negative eigenvalues to a small positive floor and rescaling back to a correlation matrix, with a warning() so this correction isn’t silent.

Simulating one study: simulate_battery()

z <- MASS::mvrnorm(n, mu = rep(0, 4), Sigma = Sigma_true)
colnames(z) <- names(specs)

for (t in names(specs)) {
  sp  <- specs[[t]]
  cal <- get_calibration(sp$mu, rel[[t]], sp$n_items, sp$guessing)
  theta <- cal$theta_mu + cal$theta_sigma * z[, t]
  p <- sp$guessing + (1 - sp$guessing) * plogis(theta)
  # 4AFC: out[[t]] <- rbinom(n, sp$n_items, p)
  # ART3: hits/rejects drawn separately, plus fp/fn rate columns
}

One MASS::mvrnorm() draw gives every simulated participant’s correlated true abilities across all four tests at once; the loop then applies each test’s own calibrated item-response mechanism. This is the function to reach for when you want one realistic dataset — every test, Vermeiren- default correlations and reliabilities unless overridden:

Simulating a focal pair: simulate_pair()

run_sweep() doesn’t use simulate_battery() — it uses a leaner sibling, simulate_pair(), that draws only the two tests under test:

d2 <- simulate_pair(n = 300, var_x = "StuVoc1", var_y = "GK",
                     true_corr = 0.2, corr_scale = "observed", seed = 2)
cor(d2$StuVoc1, d2$GK)
[1] 0.2706309
TipWhy not just reuse the full 4x4 matrix for a sweep?

A sweep deliberately pushes one cell of the correlation matrix to extreme values (including 0, to measure the false-positive rate). Doing that inside the full 4×4 Sigma_true risks exactly the positive-definiteness problem build_sigma_true()‘s eigenvalue-clipping guard exists to patch — and patching it silently changes other tests’ correlations too, which would be a confusing side effect in a sweep meant to vary only one pair. simulate_pair() sidesteps this by only ever building a 2×2 correlation matrix for the two tests actually being tested, which stays positive-definite for any correlation in (-1, 1).

corr_scale controls what true_corr means: "observed" (the default) treats it as the observed-score correlation and disattenuates internally — the right choice for NHST/power work, where the population parameter being tested lives on the observed scale (used throughout run_sweep(), below). "latent" treats it as the true-score correlation directly, with no compensation — used by sampling-measurement-error.R’s attenuation figure, where the point is to hold the construct-level relationship fixed and watch the observed correlation respond to reliability.

fit_focal_cor() is a thin wrapper around cor.test(), returning just the estimate, CI, and p-value as a one-row data frame. diagnose_cor_result() is where the teaching content lives: given the true value used to simulate the data (something a real researcher never gets to know), classify the fitted result as significant (CI/p excludes zero), sign-correct (only meaningful when the true value isn’t zero — there’s no “correct” nonzero sign to match under the null, hence NA), whether the CI covers the truth, and inflation_ratio — |estimate| / |true_value|, the Type M “how exaggerated is this estimate” ratio (Gelman and Carlin 2014), also NA under the null for the same reason sign_correct is (dividing by a true value of zero is undefined, and “exaggeration relative to zero” isn’t a meaningful question anyway).

The sweep engine: run_sweep() and summarize_sweep()

This is the script’s most distinctive piece of code — the one place the “three dials, four diagnostics” design is all visible at once — so it’s worth reading in full rather than trimmed:

run_sweep
function (n_grid, true_corr_grid, reliability_grid = NULL, reps = 200, 
    var_x = "StuVoc1", var_y = "GK", alpha = 0.05, seed_base = 1234) 
{
    rel_base <- default_reliability_vec()
    if (is.null(reliability_grid)) 
        reliability_grid <- unname(rel_base[[var_x]])
    grid <- expand.grid(n = n_grid, true_corr = true_corr_grid, 
        reliability = reliability_grid, rep = seq_len(reps))
    rows <- vector("list", nrow(grid))
    for (i in seq_len(nrow(grid))) {
        n <- grid$n[i]
        true_corr <- grid$true_corr[i]
        reliability <- grid$reliability[i]
        rep_i <- grid$rep[i]
        seed_cell <- seed_base + rep_i * 1e+06 + n * 1000 + round(reliability * 
            100) + round((true_corr + 1) * 1000)
        d <- simulate_pair(n, var_x, var_y, true_corr = true_corr, 
            reliability_x = reliability, reliability_y = reliability, 
            seed = seed_cell)
        fit <- fit_focal_cor(d, var_x, var_y)
        diag <- diagnose_cor_result(fit, true_corr, alpha)
        rows[[i]] <- cbind(data.frame(n = n, true_corr = true_corr, 
            reliability = reliability, rep = rep_i), diag)
    }
    do.call(rbind, rows)
}
NoteDeterministic per-cell seeding

seed_cell <- seed_base + rep_i * 1e6 + n * 1e3 + round(reliability * 100) + round((true_corr + 1) * 1000) gives every (n, true_corr, reliability, rep) combination its own fixed seed, derived arithmetically rather than drawn once and reused — the same scheme used by this project’s Aims 1–2 background-job simulations. The practical payoff: any single cell of a sweep can be reproduced in isolation (useful for debugging one surprising result) without re-running the whole sweep, and the whole sweep is reproducible end to end from one seed_base.

Reading this table: at true_corr = 0 (the null), power_or_type1 is the empirical false positive rate — it should sit near alpha (.05). Everywhere else, it’s power. sign_consistency and type_m_ratio are both NA at true_corr = 0 (no correct sign to match, and no meaningful “exaggeration relative to zero”) and otherwise computed only among significant results: sign_consistency is the proportion that pointed the right direction, type_m_ratio is the median inflation_ratio among them (median rather than mean, since significance filtering disproportionately selects the occasional large outlier estimate, especially at small n). coverage is the proportion of 95% CIs that actually contained the true value — should sit near .95 regardless of true_corr.

Figures: plot_metrics_vs_x() and plot_power_heatmap()

plot_metrics_vs_x(summ, x = "n", metrics = "power_or_type1", color_by = "true_corr")
plot_power_heatmap(summ, x = "n", y = "true_corr")

Both take summarize_sweep()’s output directly and are deliberately generic — any 0–1-bounded metric column (power_or_type1, sign_consistency, coverage) can be plotted against any swept dial, which is what lets the same two functions serve nhst-power.R and error-rates-process-control.R without modification.

NoteWhy type_m_ratio gets its own figure, not these two

type_m_ratio is deliberately left out of that list. Both plot_metrics_vs_x() (a shared c(0, 1) y-axis across metrics) and plot_power_heatmap() (a c(0, 1) fill scale, with cell labels formatted as percentages) assume a 0–1 proportion — true of power, sign consistency, and coverage, but not of an exaggeration ratio, which is 1 at no inflation and can comfortably exceed 2–3 at low power. Plotting it through either function would silently clip or flatten the part of the story that matters most. error-rates-process-control.R instead gives it a dedicated figure, plot_type_m_curve(), with its own appropriately scaled axis.

Common errors

Message Likely cause
reliability = ... is not achievable at mu = ... Requested reliability too close to 1 (or mu too close to the guessing floor/ceiling) for the given n_items/guessing.
Warning: achieved reliability (...) differs from the requested target (...) Calibration succeeded but landed outside tolerance of the target — usually near an achievability extreme; treat downstream diagnostics with caution.
Warning: Target observed correlation r = ... is not achievable at ... Requested observed correlation exceeds what’s reachable given the two tests’ reliabilities (\|r_true\| > 1); capped.
